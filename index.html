O que é?

Converte a interface de uma classe em outra interface que o cliente espera. Assim, classes com interfaces incompatíveis passam a trabalhar juntas.Gamma et al., Padrões de projeto (2000)

Como um adaptador de tomada: o aparelho e a parede continuam iguais, só a peça do meio é nova.

Qual a categoria?

Criação

Como os objetos são criados. Ex.: Singleton, Factory.

EstruturalAdapter

Como classes e objetos se combinam para formar estruturas maiores. Ex.: Adapter, Facade, Decorator.

Comportamental

Como os objetos se comunicam. Ex.: Strategy, Observer.

Duas formas: de objeto (composição, a que usamos) e de classe (herança múltipla).

O problema: integrar código com interfaces incompatíveis sem alterá-lo. Sem um padrão, o serviço vira um if/else por formato.

Código: o problema, antes do padrão

transaction-import-service.tssem Adapter
class TransactionImportService {
  async import(ext: string, content: Buffer) {
    let transactions: Transaction[];
    if (ext === "ofx") {
      const entries = await parseOfxFile(content);
      transactions = entries.map(/* campos do OFX */);
    } else if (ext === "xlsx") {
      const rows = await parseExcelFile(content);
      transactions = rows.map(/* campos do Excel */);
    } else if (ext === "pdf") {
      transactions = parsePdf(await extractPdfText(content));
    } else throw new Error("Formato não suportado");
    this.validate(transactions); // + regras, persistência
  }
}

Formato novo altera o serviço

Mais um else if a cada formato. Viola o princípio Aberto/Fechado.

Leitura e regra de negócio misturadas

A mesma classe sabe ler OFX e validar transações.

Difícil de testar

Não dá para testar o OFX sem passar pelo serviço inteiro.

Solução: cada tradução vira um adaptador.

Primeiro definimos o que o sistema entende. Depois, a regra que todo adaptador precisa cumprir.

A interface não menciona Excel, PDF nem OFX.

type TransactionType = "CREDIT" | "DEBIT";

interface Transaction {
  date: string;
  description: string;
  amount: number;
  type: TransactionType;
  externalId?: string;
}
2 · transaction-file-adapter.tsTarget
interface TransactionFileAdapter {
  parse(content: Buffer): Promise<Transaction[]>;
}

ofx.adapter.ts→
class OfxAdapter implements TransactionFileAdapter {
  async parse(content: Buffer): Promise<Transaction[]> {
    const entries = await parseOfxFile(content);
    return entries.map((entry) => ({
      date: normalizeOfxDate(entry.DTPOSTED),
      description: entry.MEMO,
      amount: Math.abs(Number(entry.TRNAMT)),
      type: Number(entry.TRNAMT) < 0 ? "DEBIT" : "CREDIT",
      externalId: entry.FITID,
    }));
  }
}
DTPOSTED→date
MEMO→description
TRNAMT→amount
sinal de TRNAMT→type
FITID→externalId

Validação, deduplicação e persistência ficam aqui, fora dos adaptadores.

transaction-import-service.ts
class TransactionImportService {
  async import(
    content: Buffer,
    adapter: TransactionFileAdapter,
  ): Promise<Transaction[]> {
    const transactions = await adapter.parse(content);
    this.validate(transactions);
    // deduplicação, regras de negócio, persistência

    return transactions;
  }
}
Recebe a interface, não uma classe concreta.Por isso aceita qualquer adaptador.

import-file.ts
async function importFile(
  ext: string, content: Buffer,
) {
  const adapter = adapters[ext.toLowerCase()];
  if (!adapter) {
    throw new Error("Formato não suportado");
  }
  const service = new TransactionImportService();
  return service.import(content, adapter);
}
adapter-resolver.ts
const adapters: Record<string, TransactionFileAdapter> = {
  ofx: new OfxAdapter(),
  xlsx: new ExcelAdapter(),
  pdf: new PdfAdapter(),
};

Usados junto com o Adapter

Factory

Cria ou escolhe o adaptador certo para cada entrada.

No projeto: o mapa adapters, por extensão

Strategy

Troca um algoritmo por outro em tempo de execução.

No projeto: regras de duplicidade

Parecidos, mas com outra intenção

Facade

Cria uma interface nova e simples para um subsistema. O Adapter cumpre uma interface que já existe.

Decorator

Acrescenta comportamento e mantém a interface. O Adapter muda a interface.

Proxy

Controla o acesso a um objeto com a mesma interface dele.

Bridge

Separa abstração e implementação desde o projeto. O Adapter integra o que já foi feito.

Vantagens

  • Responsabilidade únicaA conversão fica separada da regra de negócio.
  • Aberto/FechadoFormato novo é uma classe nova, sem alterar o serviço.
  • Reaproveita o que existeBibliotecas e código legado são usados sem modificação.
  • Testes isoladosCada adaptador pode ser testado sozinho.

Desvantagens

  • Mais classes e interfacesAumenta a complexidade geral do código.
  • Uma camada a maisA indireção dificulta entender e depurar o fluxo.
  • Pode ser exageroSe a classe original pode ser alterada, às vezes é mais simples.
  • Conversões pesadasInterfaces muito diferentes exigem muito código de tradução.
